# StreamSense Memory Dashboard

Memory is the accessible browser surface for the same sessions generated by the
StreamSense Live extension. Capture, narration, questions, and interruption
remain in the side panel; Memory reads bounded REST projections from the shared
backend.

After the protocol-v2 handshake, Live receives the real session UUID. **Open
Memory Dashboard** opens `/dashboard/sessions/{sessionId}?source=extension` or
the overview when no session is active. The active session page refetches its
session, events, and graph every two seconds. This is bounded REST polling, not
a second realtime WebSocket client.

## Run

Integrated development from the repository root:

```bash
npm install
npm run dev
```

Open `http://127.0.0.1:5174/dashboard/`. The Vite server proxies `/api` to the
backend on `8000`.

Dashboard-only development:

```bash
npm run dev:dashboard
```

Built one-backend profile:

```bash
npm run demo
```

Open `http://127.0.0.1:8000/dashboard/`.

None of these normal commands seed synthetic sessions. With MongoDB configured,
Memory loads durable real Live history. Without MongoDB it starts empty and
history is process-local.

## Routes

- `/dashboard/` — session overview and multi-domain relationship map;
- `/dashboard/sessions/:sessionId` — session summary, relationship map, and
  chronological timeline;
- `/dashboard/search` — semantic search over durable events;
- `/dashboard/account` — prototype MongoDB-backed profile preferences;
- `/dashboard/explore` — compatibility redirect to overview/session
  relationships.

## Data source

The dashboard never talks directly to Gemini, Cloud STT, SQLite, MongoDB, or an
embedding provider. It consumes:

- `GET /api/sessions`
- `GET /api/sessions/:sessionId`
- `GET /api/sessions/:sessionId/events`
- `POST /api/search`
- `GET /api/context-graph`
- `/api/accounts`

When MongoDB is configured, those history resources are backed by durable
`sessions` and `events` collections. The same event document contains
chronological fields and optional semantic embedding fields. An embedding-only
partial document is not exposed until the real history archive marks it as
accepted.

## Relationship map

The map uses Memory → domain → session → event → entity/topic. Multi-domain
views use:

- X — normalized stream progress;
- Y — supplied event importance;
- Z — entertainment lane.

Single-session/single-lane maps use a truthful progress × importance 2D
projection. The client never fabricates semantic similarity. Every canvas node
and edge has a readable selector/details/list alternative. Reduced motion
removes camera easing; WebGL failure leaves the DOM representation usable.

## Accessibility

- semantic headings, landmarks, status, loading, empty, and error states;
- skip link and visible focus;
- route focus management;
- keyboard-accessible graph node selector and links back to timeline events;
- OS forced-colors support;
- reduced-motion support;
- normal DOM chronological timelines and relationship lists.

Visible shortcuts:

| Shortcut | Action |
| --- | --- |
| `Ctrl+K` | Open/focus Memory search. |
| `Alt+H` | Open Memory overview. |
| `Alt+G` | Focus the graph node selector. |
| `Alt+/` | Open shortcut help. |
| `Escape` | Close help and restore focus. |

## Account scope

The Account route stores a prototype display name, normalized email, and
preferences in MongoDB. Browser storage contains only the opaque account UUID.
This is not production authentication, and current session history is not yet
partitioned by account ID.

## Finals data policy

The normal dashboard must show real sessions captured through Live. Synthetic
fixtures remain test-only. To prepare judge-ready history, run the real
extension against selected clips in advance and keep those MongoDB sessions.
During the live demo, the newly opened session appears alongside that genuine
captured history and survives backend restart.

```bash
npm run check --workspace session-dashboard
```

The full repository gate is:

```bash
npm run check
```

exact session opened from Live and remains after backend restart.
