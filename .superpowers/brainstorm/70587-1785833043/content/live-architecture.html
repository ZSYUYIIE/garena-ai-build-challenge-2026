Backend-mediated Gemini Live architecture

One Live session receives the user microphone and sampled screen frames. Tab audio never leaves the extension.

Chrome extension side panel
Visual context

Tab frame sampler

Captures a JPEG at up to 1 FPS, sends material changes, and forces a fresh frame when the user starts a question.

Conversation input

User microphone

Open mic produces mono PCM for Gemini VAD and natural barge-in.

Local control only

Tab speech detector

Observes captured-tab audio and emits only speaking / quiet. Its audio is never sent to Gemini.

Output

Native audio player

Plays Gemini audio, displays transcripts, and immediately clears queued playback on interruption.

Local StreamSense backend
Session boundary

Live session orchestrator

Owns one authenticated Gemini Live WebSocket per extension session and relays audio, video, transcripts, and lifecycle events.

Polite narration

Narration gate

Prompts Gemini only after a meaningful visual change when the tab is quiet. User speech always has priority.

Structured memory

Event tool adapter

Validates Gemini function calls before recording timeline events in the existing event store.

Provider connection

Gemini Live

Receives microphone PCM, changed JPEG frames, and narration triggers; returns native audio plus input/output transcripts.

Source isolation

Gemini receives

  • User microphone audio
  • Sampled screen frames
  • Backend narration prompts

Gemini never receives

  • Captured-tab audio
  • Browser speech-synthesis output
  • Permanent API credentials in the extension
